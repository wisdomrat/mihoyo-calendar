## 0. 为什么存在 V2

`candidate-01` 是一份认真、可实现的保守方案，但它仍然保留了现有产品的主要视觉骨架：

- 顶部标题、搜索和操作行
- 左侧常驻筛选栏
- 右侧圆角日历容器
- 容器顶部横向工具条
- 暗色表面亮度台阶
- 有内容日期填充为小卡片
- 日期格中排列圆形角色头像
- 2px 阵营色条和轻描边作为主要主题反馈

这不是候选模型单方面的问题。V1 把部分“现有解决方案”误写成了“必须保留的功能”，又允许模型回读现有组件和 CSS，因而产生了设计锚定。

V2 做三项修正：

1. 功能以黑盒能力描述，不规定侧栏、顶栏、抽屉、弹窗等具体容器。
2. 候选阶段禁止读取现有 UI 实现、CSS、截图和其他候选方案。
3. 加入结构差异门槛和“标志性机制”评分，单纯精修旧骨架不能通过。

V2 的目标不是为了不同而不同。它要求模型重新推导结构，再用功能、可访问性和性能验证这个结构。

## 2. 产品事实，不包含现有设计

### 2.1 产品是什么

这是一个米哈游角色生日与首次实装纪念日日历。用户在一年循环中查看角色日期、筛选游戏与角色属性、搜索角色、收藏角色、查看立绘和详情，并导出提醒。

它首先是一个可反复使用的日历工具，其次是一个承载游戏角色和阵营气质的内容产品。它不是营销落地页、KPI Dashboard、社交产品或账号系统。

### 2.2 用户任务优先级

1. 扫描某个月哪些日期有角色事件。
2. 看清某一天涉及哪些角色、来自哪个游戏。
3. 缩小范围：游戏、属性、稀有度、武器类字段、地区类字段、收藏。
4. 搜索角色并跳到对应日期。
5. 查看角色详情、立绘和归属。
6. 切换月/周和生日/实装纪念日语义。
7. 调整显示偏好。
8. 导出 ICS/JSON、添加/编辑角色、更新数据。

### 2.3 技术和数据边界

- React 19、TypeScript、Vite、`date-fns`、纯 CSS。
- 纯前端，无业务后端。
- 角色数据和用户偏好保存在 `localStorage`。
- 使用项目内真实角色数据、头像和立绘。
- 无现成 UI 框架。
- 未来正式实现可以替换全部展示组件，但复用现有 hook、类型和业务工具。

## 3. 黑盒功能契约

本节只规定用户能完成什么，不规定控件位于顶部、左侧、抽屉或弹窗。

### 3.1 时间浏览能力

- 查看完整月历；月视图保留用户熟悉的 7 列星期拓扑。
- 查看一周内容；周视图的具体空间结构由候选重新设计。
- 前往上一个/下一个月或周。
- 回到今天。
- 跳转指定年月。
- 选择周日或周一作为一周起点。
- 区分今天、当前月、补位日期、有事件、无事件和事件溢出。
- 非闰年的 2 月 29 日年度映射必须明确、不误导。

### 3.2 日期语义能力

- 在生日和首次实装纪念日之间切换。
- 生日以 `MM-DD` 每年重复。
- 实装日期来自 `YYYY-MM-DD`，日历按月日展示周年，详情可展示完整日期。
- 星穹铁道强制使用实装日期，因为没有可靠官方生日。
- 崩坏3在缺少完整实装数据时回落到生日。
- 不允许某个游戏因模式切换而错误地变成空数据。

### 3.3 角色内容能力

- 月视图提供头像、卡片、紧凑三种密度偏好；它们可以被重新解释，但必须可切换且有明显差异。
- 用户能从日期进入当天全部角色，再进入单个角色详情。
- 图片缺失或加载失败时有稳定回退。
- 同一天角色过多时不破坏网格，也不静默丢失角色。

### 3.4 范围与筛选能力

支持四个游戏：原神、崩坏：星穹铁道、绝区零、崩坏3。

- 多选游戏。
- 为不同游戏维护彼此隔离的二级筛选。
- 原神：元素、稀有度、武器、地区。
- 星穹铁道：属性、稀有度、命途、阵营。
- 绝区零：属性、稀有度、特性、阵营。
- 崩坏3：属性、稀有度、类型、组织。
- 显示/隐藏信息不全的角色。
- 看见活跃筛选数量和当前范围。
- 清除筛选。
- 所有游戏均未选择时有可恢复的空状态。
- 桌面和移动端都必须能高效完成筛选，但交互容器由候选自行决定。

### 3.5 搜索与定位能力

- 搜索全部角色，不受当前筛选结果限制。
- 可匹配中英文名、游戏、生日、属性、武器类字段和地区类字段。
- 名称匹配优先，默认最多 8 项。
- 支持 `ArrowUp`、`ArrowDown`、`Enter`、`Escape`。
- 选中后跳到对应月份，并进入角色上下文。

### 3.6 角色详情能力

- 展示中英文名、游戏、当前日期语义、稀有度、属性、武器类字段、地区类字段。
- 展示头像或立绘，并支持仅看立绘。
- 支持静态/动态立绘偏好。
- 收藏/取消收藏。
- 导出单角色 ICS。
- 进入编辑流程。
- 关闭和返回路径明确。

### 3.7 内容维护与数据能力

- 添加和编辑角色。
- 表单输入、头像 URL、本地图片上传和预览。
- 单条或数组 JSON 导入。
- 导出全部角色 JSON。
- 导出有效生日/实装纪念日 ICS；无有效事件时给出反馈。
- 更新已发布角色数据，展示进度、结果和最后更新时间。
- 不增加角色删除 UI、账号、云同步、邮件服务或后端。

### 3.8 持久化能力

正式实现必须继续持久化：角色数据、显示密度、周起始日、筛选、立绘背景、动效、日期模式、收藏、主题跟随和最后同步时间。

## 4. 阵营上下文能力

项目已有 `resolveAffiliation(character)` 概念，能返回归属名称、标语和 `key/accent/deep` 三个颜色。候选只需要围绕该输入设计，不需要读取其当前 UI 用法。

当前数据覆盖：

- 原神已有多个地区级归属。
- 绝区零已有多个阵营级归属。
- 星穹铁道和崩坏3目前只有游戏级 fallback；不得虚构更细映射。

目标不是“点谁就整页换皮”，而是建立可识别、可扩展的上下文反馈：

- 游戏提供基础视觉语法。
- 地区/阵营提供局部差异和一次性反馈。
- 角色提供具体图片与内容。
- 结构和操作含义在切换时保持稳定。
- `motionEnabled=false` 和 `prefers-reduced-motion` 下信息不能丢失。

候选必须自行决定上下文反馈发生在哪里、持续多久、强度多大。V2 不预设它必须是色条、边框、背景、粒子、纹理或弹窗。

## 5. 结果约束，不规定解决方案

### 5.1 目标视口

- 1440 × 900
- 1280 × 800
- 1024 × 768
- 768 × 1024
- 390 × 844
- 360 × 800

### 5.2 可用性结果

- 无页面级横向滚动。
- 月视图 7 列不会被图片和长文本撑宽。
- 中文长游戏名、阵营名和角色名有稳定处理。
- 移动端触控目标稳定，不因内容变化跳动。
- 浮层超高时可滚动，关闭/返回始终可达。
- 不能只靠颜色表达今天、选中、收藏、错误和筛选状态。
- 搜索和所有核心操作可键盘使用。
- 动效支持 reduced-motion。
- 不为每个日期格运行持续粒子、模糊或滤镜动画。

### 5.3 真实内容结果

- 使用真实角色头像/立绘或真实字段的代表样本。
- 不生成虚假活动、统计、用户、阵营或业务功能。
- 角色图片是内容，不是无关背景素材。
- 在没有图片的情况下，界面仍然成立。

### 6.2 旧结构指纹

以下组合代表需要摆脱的旧结构。它不是禁止单个元素，而是禁止整体继续同构：

1. 顶部一行标题、搜索、收藏和添加。
2. 左侧固定筛选栏，右侧日历。
3. 日历被包在一个大圆角深色容器中。
4. 所有视图与显示设置横排在日历容器顶部。
5. 有事件日期显示为深色小卡片，里面排列圆头像。
6. 主要阵营反馈只是顶部细色条、描边和轻微换色。
7. 角色详情是居中圆角弹窗，立绘作为背景、信息压在其上。

最终候选不得同时保留其中 4 项或以上。保留任一项都必须说明它为何是从用户任务重新推导出来，而不是继承习惯。

### 6.3 形态探索门槛

开始原型前，候选必须制作一个形态矩阵，至少探索以下五个轴：

| 设计轴 | 至少比较的不同可能 |
|---|---|
| 全局导航 | 顶部、侧边、局部命令区、上下文导航、其他 |
| 筛选交互 | 常驻、临时模式、分步聚焦、命令面板、内联范围、其他 |
| 日期内容 | 头像簇、文字条、密度标记、主次角色、图文混合、其他 |
| 角色详情 | 侧边检查器、内联展开、独立场景、覆盖层、其他 |
| 阵营表达 | 空间、材质、排版、运动、声音之外的视觉节奏、其他 |

至少画出 5 个差异明显的低保真缩略线框，不能只是移动同一组按钮。先淘汰 4 个，再选择最终方向。

### 6.4 标志性机制

最终方案必须同时拥有：

- 一个结构性标志：仅看灰度布局轮廓，也能和旧页面明显区分。
- 一个内容性标志：能把“角色日历”与普通日历区分。
- 一个上下文标志：阵营变化不只靠换主色。

三个标志必须能用一句话分别说清楚，并在原型截图中直接看见。长篇设计说明不能替代可见差异。

### 6.5 手法自由

可以使用玻璃、霓虹、渐变、纹理、粒子、插图式排版、强对比色、非对称构图或大胆动效。要求是：

- 至少有一个具体产品语义。
- 有清晰出现范围，不全站无差别铺开。
- 不损害日历扫描和文字对比。
- 有移动端、低性能和 reduced-motion 退化。

不要因为 V1 曾提醒过常见 AI 风格，就自动选择最安全、最中性的方案。V2 明确鼓励一个大胆、可识别、受控制的视觉主张。
