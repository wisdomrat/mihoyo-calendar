## 一、高度一致的核心判断（无需调和）

### 1. 圆角语言

- **审核 P0-1**：主容器 8px 对 GPT `rx=26`，建议 24–28px。
- **refinement-brief §2.9**："GPT 的圆角只有两档：26px 大容器 + 全圆胶囊"（隐含约束，未明确要求 26px）。
- **一致性**：✅ 审核建议 26px 精确对齐母版，与 brief 的"保留 GPT 不变量"一致。

### 2. ThemeProfile 机制本身可采纳

- **审核 §3 判定**：ThemeProfile 合同"有条件通过"，14/14 字段全部真实消费。
- **visual-theme-analysis §3**：建议采用 `ThemeProfile + 场景图层`，不做"每个角色一套 CSS"。
- **一致性**：✅ 审核确认了 analysis 文档的机制方向。

### 3. 光晕位置可变性

- **审核 P1-2**：光晕位置应为 profile token，GPT `02` 在须弥态把光晕移到 `cx=27% cy=15%`。
- **visual-theme-analysis §1.2**："主径向光晕移到左上并使用薄荷青"。
- **一致性**：✅ 审核证实了 analysis 观察到的"位置本身属 profile"。

### 4. 三套并行主题源问题

- **审核 P0-3**：候选手工 5 profile 与生产 `resolveAffiliation()` + `useTheme` 构成三套并行。
- **visual-theme-analysis §2.1**："主题来源分三层…地区主题存在时地区优先于游戏色"。
- **roadmap §3**：保留 `affiliations*.ts` 和 `useTheme` 为业务层。
- **一致性**：✅ 审核发现的冲突正是 analysis 与 roadmap 要避免的方向。

### 5. Hero 应为场景修饰符而非独立 profile

- **审核 P1-1**：`hero` 被建模成 profile，关闭后强主题永久残留。
- **visual-theme-analysis §4**："全屏 Hero 是最适合使用强主题的地方…关闭后回到日历"。
- **prep §1**："保留能力，合并视觉职责"，不同时保留全屏 Hero + 工作区舞台。
- **一致性**：✅ 审核建议"Hero 不是 profile，只施加 heroStrength"与既有决议完全对齐。

### 6. 头像密度机制

- **审核 §3 判定**：头像机制"有条件通过"，结构上不可能推动日期数字。
- **refinement-brief §三.B**：单角色 48–64px（受行高限制）；2–3 位重叠 25–35%；4+ 位最多 3 个 + `+N`。
- **roadmap §5**：三档规则应是自动布局，`displayMode` 不再决定完全不同页面结构。
- **一致性**：✅ 审核确认机制成立，尺寸建议与 brief 一致（审核给出 44–52px 为下限）。

### 7. 控件分层

- **审核 §7**：常驻 6 项 + 可展开面板 + 独立状态，首屏不超过 10 个。
- **refinement-brief §三.A**：常驻包括"上月/下月、今天、月/周、生日/实装、筛选摘要、搜索"。
- **roadmap §2**：P0 首屏功能 vs P1 展开 vs P2 低频。
- **一致性**：✅ 审核的控件分层直接采纳了 brief 与 roadmap 的三级划分。

### 8. 移动端顶部带高度

- **审核 P0-2 影响段**：GPT `04` 顶部带约 44px；候选因 profile 切换器撑到 102px。
- **审核 §8.25**：移动端顶部带不超过 56px。
- **refinement-brief §三.E**："移动端顶部不要堆放所有功能"。
- **一致性**：✅ 56px 是对 GPT ≈44px 的合理工程上限。

## 二、审核补充的细节约束（既有文档未明确）

以下约束由审核新增，但**不与既有决议冲突**，应当采纳：

### 1. 容器边框/阴影（P0-1、P1-6）

- 既有文档：未明确禁止或要求阴影。
- **建议**：采纳审核的"边框 12–18% alpha、禁止 drop shadow"作为冻结合同补充。

### 2. 面板不透明度（P1-6）

- 既有文档：未明确要求具体值。

### 3. 双栏间距与留白（P1-7）

### 4. 选中态/今天态材质（P1-11）

- 审核发现：候选用 accent 着色格 + 内环，GPT 用浅珍珠药丸。

- **建议**：采纳审核的"accent 严格限定在舞台边框/头像环/事件点/焦点/摘要"。

### 6. 两类事件并存（P1-13）

- 审核发现：候选实现为互斥硬筛选，GPT 在同一网格同时渲染生日与实装。

- **建议**：采纳审核的"两类并存、以颜色区分"，该 segmented 降级为"强调"或移入展开面板。

### 7. 字距语汇（P1-16）

- 审核发现：候选通配 `letter-spacing:0`，GPT 小号大写标签 1.6–4px。
- 既有文档：未明确要求字距。
- **建议**：采纳审核的"eyebrow/标签 1.4–2.5px、品牌 2–3px"。

### 8. 立绘压暗曲线（P1-12）

- 审核发现：候选 2 停靠点线性、64% 处 .436；GPT 3 停靠点、64% 处 .17。

### 9. 辅助光尺寸与强度（P2-4）

- visual-theme-analysis §1.1：只说"低透明度模糊光源"。
- **建议**：采纳审核的"18–22% 半径、7–9% 透明度"。

### 10. 短视口裁切（P1-8）

## 四、既有决议未覆盖、审核首次提出的机制风险

- 既有文档：未要求"同月同数据验证纯 token"。
- **影响**：审核 §9 要求下一轮 6 张截图必须"同月同数据（2026-08）+ 生日实装并存"，用于隔离色彩变化。
- **建议**：采纳该验收要求，写入最终视觉合同。

### 2. 整画布截图掩盖浏览器布局失败（P1-8 说明段）

- 审核指出：6 张截图为整画布输出、不含浏览器 chrome，因此**无法暴露短视口裁切**。
- 既有文档：未明确区分"整画布截图"与"真实浏览器截图"。
- **影响**：审核 §9 要求一张 1440×768（而非 900）验证短视口。
- **建议**：采纳，并在下一轮明确"截图须为真实浏览器窗口，含 chrome"。

### 3. 移动端 `+N` 少报一位（P1-5）

- 审核发现：`.avatars.dense .avatar:nth-child(n+3){display:none}` 隐藏第 3 个，N 仍按 `people.length-3` 算 → 5 人显示 2 头像 + `+2`，实际隐藏 3 人。
- refinement-brief §三.B：只说移动端"约 18–24px 小头像 + `+N`"，未说 N 的计算规则。
- **建议**：采纳审核的"N 由实际渲染数导出"，写入冻结合同 §21。

### 4. 图片失败回退只覆盖 1/4 场景（P1-3）

- 审核发现：`setImage()` 只对舞台绑 `onerror`，头像/Hero/搜索三处无回退，与 README:31 声明冲突。
- roadmap §2.P0："角色头像/立绘缺失时的文字回退"。
- prep §2："无图回退…确认文字回退仍然符合视觉系统"。
- **影响**：roadmap 与 prep 已要求此能力，审核发现候选未实现。
- **建议**：在冻结合同中明确"首字母回退覆盖舞台/日历头像/Hero/搜索全部四处"（审核 §8.22）。
