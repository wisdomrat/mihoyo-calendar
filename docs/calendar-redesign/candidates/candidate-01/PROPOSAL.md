## 预备说明：内部比较过的三个方向（淘汰两个）

| 方向 | 一句话 | 淘汰原因 |
|---|---|---|
| A. 扫描板（工具优先） | 亮色中性桌面 + 发丝线网格，游戏身份退化为 8px 色点，零装饰 | 扫描效率最高，但评分中「游戏/阵营辨识度」占 20%、「情绪和辨识度」是产品目标明文要求；且与已上线的暗色影院 Hero 形成硬断裂，衔接无法成立。纯亮底也让 `resolveAffiliation` 的 key/accent/deep 三色体系（为暗底设计）无处安放。 |
| B. 影院延续（氛围优先） | 阵营色大面积渲染工作区背景，立绘渗进日历底纹，玻璃面板漂浮 | 直接命中任务书第 6 节列出的两个失败模式：「只追求大图和氛围，日历退化为 Hero 附属」；阵营色做底会威胁正文对比（用户硬约定：文字任何主题下必须看得清）；21 个角色/天的密度日（实装模式 09-15）在氛围底上完全不可扫描。 |
| **C. 一台两面 · 边光（采纳）** | 日历是恒定不变的「舞台」，归属上下文只作为「边光」从边缘进来：色条、描边、低对比纹理，不改表面、不动结构 | —— |

方向 C 的核心判断：这个产品的视觉资产是**角色本身**（288 个真实头像、255 张立绘），不是背景氛围。工作区的职责是让角色内容以最高效率被扫描，归属感靠**边缘的、可退回的光**来表达——这正是任务书 4.2「允许变化 vs 必须稳定」三级表的直译。

---

## A. 一句话设计主张

**七列日历是永不换景的舞台，归属是流动的边光：网格、亮度台阶和控件位置恒定不变，游戏与阵营的身份只从四条边缘进入——顶部 2px 色条、今日格描边、侧栏接缝、一层低对比纹理。**

### 频率分层与放置理由

| 频率 | 操作 | 放置 | 理由 |
|---|---|---|---|
| **高频** | 上/下月（周）、回到今天、点击角色、月/周切换 | 日历工具条，始终可见 | 每次会话重复十几次，必须零寻找；放进日历容器顶部，声明「这些是日历的控件」 |
| **高频** | 搜索 | 工作区条始终可见（桌面）/ 图标展开（移动） | 搜索是「跳转到某角色」的导航行为，属于全局产品层，不从属于日历也不从属于筛选 |
| **中频** | 游戏多选、二级筛选、收藏范围、显示模式、日期模式 | 筛选面（侧栏/底单）；显示模式、日期模式同时在工具条 | 筛选需要面板承载 4×4 组标签；显示模式/日期模式改变「网格画什么」，留在日历工具条 |
| **中频** | 收藏开关 | 工作区条 ★n 按钮（pressed 态） | 收藏是范围开关也是计数展示，需要常显反馈 |
| **低频** | 周起始日、主题跟随、立绘背景、动态效果、导出、更新、最后更新时间 | ⋯ Popover，两组（显示与动效 / 数据），全部带文字标签 | 一次设定多次生效；常显会与日历争主视觉。Popover 内用完整文字标签而非图标，保证可发现性 |
| **低频** | 添加角色 | 工作区条 ＋（唯一实心主按钮） | 唯一的内容创建入口，保留常驻但整行只允许一个实心按钮 |

**始终可见 vs 收纳的判断标准**：是否会改变「当前日历在显示什么」（是→常显），是否每次会话都调（是→常显），否则收纳。

### 尺寸与滚动责任

| 项 | 值 |
|---|---|
| 内容最大宽度 | 1400px，水平 auto 居中；两侧留白 ≥20px |
| 工作区条高度 | 56px，不参与 sticky（Hero 之后自然滚入） |
| 侧栏宽度 | 展开 272px / 折叠 0px（整列收回，工具条出现「筛选 ③」入口钮） |
| 侧栏与日历间距 | 20px |
| 日历容器 | `flex:1; min-width:0`；内部 padding 20px |
| 格子 | 7 列等宽 `minmax(0,1fr)`，列间距 8px；`aspect-ratio: 1.32`，min-height 76px |
| 滚动责任 | **页面滚动是唯一滚动**（桌面月视图必须整月可见，日历内部不滚动）；侧栏超高时自身滚动（`position: sticky; top:16px; max-height: calc(100dvh-32px)`）；弹窗内部滚动 |

1440×900 垂直预算：56(条) + 24(距) + 52(工具条) + 28(星期) + 6×104(行) + 5×8(行距) + 40(容器padding) ≈ 808px ≤ 900 ✓（6 行月份；5 行月份更宽裕）。

### 1280×800 压缩策略

- 侧栏保持 272px（不自动折叠——用户的筛选状态值得尊重）；日历收窄至 ≈930px，格宽 ≈124px，头像 30px 不变，头像模式每格容量自然从 ~12 降到 ~8，溢出更早进入 +N，这是**正确行为**不是损失。
- 高度 800：6 行月份行高降至 ≈92px（aspect-ratio 让位给 `max-height`，格子最低 76px 保底）；工具条间距收一档（gap 20→12）。
- 若用户手动折叠侧栏，日历回收全部 292px（272+20），格宽回到 ≈150px。

### 侧栏三态

| 状态 | 表现 |
|---|---|
| 展开（默认 ≥1280） | 完整面板：游戏 4 行 → 分隔 → 「显示信息不全」→ 当前游戏二级筛选 → 底部「清除筛选」文字钮（仅 count>0） |
| 折叠 | 整列 width 0（200ms 收起）；日历工具条左端出现 `筛选 ③` 钮（徽标=活跃数）；再点展开。**不给 56px 窄轨**：窄轨只能放一个图标，信息量为零却永久占用 56px 日历宽度 |
| 所有游戏取消选择 | 日历容器保留（不塌），网格位置换成空状态面板：「没有选中任何游戏」+ 一行说明 + `恢复全部四个游戏` 按钮；侧栏内 4 个游戏行全部呈未选态可重新勾选。不渲染空网格——空网格会谎报「这个月没人过生日」 |

### 390×844（主流手机）

```
┌────────────────────────┐
│ ◆ 生日日历   🔍  ★12  ＋ │ L0 52px：4 个 44×44 触控目标，标题缩为短称

│ 月│周 生日│实装 ▦显示 筛选③│ 行 B 44px（sticky）：▦=显示模式弹单（3 选 1）
│ 日 一 二 三 四 五 六      │ 24px，字号 12
│ ┌──┬──┬──┬──┬──┬──┬──┐ │ 格宽 ≈48px，行高 ≈56px
│ │26│… │  │  │  │  │1 │ │ 头像 20px，每格 ≤4 枚 → +N
│ ├──┼──┼──┼──┼──┼──┼──┤ │
│ │  │  │  │  │  │17│  │ │ 17 = 今日徽标（accent 圆点）
│ └──┴──┴──┴──┴──┴──┴──┘ │
```

- **搜索**：🔍 点击后 L0 行原位展开为整行输入框（标题/图标让位），结果下拉 panel 最大高度 60dvh；Escape/取消钮收回。不占用常驻宽度。
- **日期格溢出**：手机格容量约 4 枚头像，第 5 枚起 `+N` 圆钮；点击格任意处或 +N → 当天面板（底部弹出，非居中，单手可达）。
- **详情弹窗**：≤1024px 改为**底部抽屉式**（宽 100%，圆角只在顶部，max-height 88dvh，内部滚动），立绘作为抽屉顶图（16:9 裁切位）而非全屏背景——手机上立绘铺满弹窗会让文字无处安放。操作区（收藏/ICS/编辑）sticky 在抽屉底部，永远不离屏。
- **编辑表单**：同一抽屉形态；表单字段单列；键盘弹起时容器内滚动，提交钮保持在可视区。
- **周视图 ≤1024px**：7 列改为**纵向日清单**（每日一节：日期标签 + 条目纵排），桌面 ≥1025px 保持 7 列。原因：手机宽 7 列每列仅 ≈50px，容纳不下契约 3.3 要求周视图呈现的「名字 + 游戏归属」。原型 `@media (max-width:1024px)` 的 `.week-grid` 已按此实现。

### 1024px 断点切换的具体规则（不是「响应式适配」一句带过）

| 条件 | 布局 | 切换内容 |
|---|---|---|
| ≥1025px | 桌面形态 | 侧栏（sticky）+ 弹窗居中 + 搜索常显输入框 |
| ≤1024px | 触控形态 | 侧栏 DOM 不渲染（不是 display:none 藏 272px）；筛选底单启用；详情改抽屉；工具条拆两行；触控目标下限 44px |
| 1024↔1025 来回 | 断点以 CSS media + JS `matchMedia` 双轨（CSS 控样式、JS 控 DOM 挂载） | 筛选状态存于 hook 层，跨断点无损；打开中的底单在变宽时关闭并同步到侧栏 |

### 360×800 窄屏防溢出

- 页面左右 padding 收至 6px；7 列 + 6×2px 间隙 = 格宽 ≈46px。
- 头像模式头像 18px；紧凑模式点 6px；卡片模式：头像 20px + **下方单行名字 11px ellipsis**（名字永远单行，不允许换行撑高/撑宽）。
- 星期标签用单字（日一二…）；`2026年8月` 标题字号 15px 可容；工具条行 B 的段控用纯图标+aria-label（月/周例外，保留文字因为它是视图语义）。
- 长名「崩坏：星穹铁道」只出现在详情与筛选面板（可换行区），网格内一律用短名「星穹铁道」且受 ellipsis 约束。
- 校验标准：`documentElement.scrollWidth === clientWidth`（沿用项目既有验证惯例）。

## E. 月视图与周视图规范

### 信息密度与层级

| | 月视图 | 周视图 |
|---|---|---|
| 任务 | 「这个月哪天有谁」——密度扫描 | 「这 7 天的完整名单」——逐条阅读 |
| 每格承载 | 头像/点阵 + 日期号；名字只在卡片模式出现 | 完整条目：头像 + 名字 + 游戏短名，竖向列表 |
| 视觉层级 | 1 日期号 → 2 填色（有无角色）→ 3 头像层 → 4 今日/锚点描边 | 1 表头（周几+日期，今日强调）→ 2 条目（游戏色左缘 2px）→ 3 空日提示文字 |
| 无角色日 | 留白（只有日期号） | 文字「无角色生日 / 无角色实装」（随日期模式） |

移动端（≤1024px）周视图不做 7 列，做**纵向日清单**：每日一节（日期标签 + 条目纵排），条目结构与桌面一致；桌面保持 7 列横排。理由见 D 节——契约要求周视图呈现名字与归属，7 列在手机宽度下做不到。

### 日期格状态矩阵（8 态）

| 状态 | 视觉规则 | 非颜色冗余信号 |
|---|---|---|
| 普通（本月·无角色） | 透明底，日期号 `--ink-soft` | 留白本身 |
| 今天 | 底 `color-mix(accent 15%, surface-2)` + inset 1px accent 环；日期号变 accent 底圆徽、`--accent-ink` 深字 | 圆徽形状（唯一带环的格） |
| 非当前月 | opacity .45（无角色）/ .6 + 降饱和填色（有角色）；日期号 `--ink-faint` | 整体淡出，且排在网格首尾 |
| 有角色（1~N） | 填 `--surface-2`；日期号升 `--ink-strong` | 填色 vs 留白 |
| 多角色 | 同上；头像自然多行排布（头像模式）/ 点阵（紧凑） | 数量即所见 |
| 溢出 | 容量测得后保留最后 1 槽给 `+N` 圆钮（surface-3 底）；title=「查看全部 N 个角色」 | 数字文本 |
| 选中上下文（搜索锚点） | 跳转后目标格 1.5px `--affil-accent` 环 + 1.2s 单次脉冲后静止为普通选中环（保留到下次导航） | 环 + 详情弹窗同时打开互为佐证 |
| 非闰年 2 月 29 日 | **幽灵格**：仅当当前日期模式下存在 02-29 映射角色时追加在 2 月网格末尾；虚线 1px 边（`--line-strong`）、日期号 29 淡化 + 角标「本年无 2/29」；角色照常显示可点。周视图中该周 2/28 格内附一行「2/29（本年无此日）· N 位」分隔区。详情永远显示真实 02-29 | 虚线 + 文字说明双保险 |

现有数据中的落点（真实数据验证）：生日模式 班尼特(02-29)、花火(02-29→星铁强制实装后为 02-06)；实装模式 米沙(2024-02-29)。2026 非闰年 → 幽灵格在生日模式显示 1 位、实装模式显示 1 位。

### 三种显示模式的网格稳定性

- 三模式共用同一外壳：同 7 列轨道、同 `aspect-ratio`、同日期号行高 20px。**模式只换格内内容层，不换网格**。
- 头像模式：30px 头像 + 2px 游戏色环；容量由 ResizeObserver 实测（沿用现有 `useCellCapacity` 模式，用 `offsetWidth` 防悬停 scale 抖动）。
- 卡片模式：头像 24px + 单行名；**同样受容量限制**（现实现卡片模式不做容量截断，09-15 这类 21 人日会把格子撑破——本方案修复为统一容量 + `+N`）。
- 紧凑模式：8px 游戏色点，容量最大；用于极限密度扫描。
- 行高由 grid 行内最高格决定，`aspect-ratio` 保证同行一致；任何模式切换不产生列宽变化。

### 图片缺失与加载失败回退

- 无 avatar：首字回退块（游戏色 15% 底 + `--ink-strong` 首字）。现有 33 个 ui-avatars 占位头像按真实头像对待（数据层已有评分逻辑，视觉层不感知）。
- `onError`：隐藏 img，原位替换为首字块（同尺寸，不重排）；同 URL 记入会话级黑名单防重试风暴。
- 所有头像槽固定宽高 + `loading="lazy"`；加载前后占位一致 → 零布局跳动。

## H. Context Theme System（边光系统）

### 概念数据流

```
用户点击任意角色（日期格/周条目/当天面板/搜索结果/Hero）
        │
        ▼
selectedCharacter ──► useTheme(selectedCharacter, selectedGames)
        │                    └─► ThemeId: neutral | 游戏级   → .app[data-theme]
        │
        └────────────► resolveAffiliation(character)          （纯函数 O(1) 查表）
                             └─► { id, name, tagline, ink,
                                   colors: { key, accent, deep }, bg }
                                   │
                                   ▼
        App 注入 .app：data-affiliation="<id>" + 内联 --affil-key / --affil-accent / --affil-deep
                                   │
                                   ▼
        CSS：--accent-rule、今日环、侧栏接缝、效果层纹理 读取 affil 变量（color-mix 混入主题 accent）
```

关键纪律：**affil 变量只喂给「边光」属性**。`.app`、`.calendar-container`、格子的表面色一律不读 affil——这是「结构稳定」的物理保证，不靠约定靠依赖关系。

### Token 表

| Token | 职责 | 中性默认 | 游戏级变 | 阵营级变 |
|---|---|---|---|---|
| `--bg / --bg-accent` | 页面基底/凹陷 | #101115 / #0c0d10 | ✔（5 套既有亮度骨架，6~9 L* 台阶） | ✘ |
| `--surface / -2 / -3` | 工作面阶梯 | #212429 起 | ✔ | ✘ |
| `--ink / strong / soft / faint` | 四级墨色 | 暖白系 | ✔ | ✘ |
| `--line / -soft / -strong` | 三级边框（暗底亮边） | 石墨系 | ✔ | ✘ |
| `--accent / --accent-2 / --accent-ink` | 主题双强调+压强调深墨 | 靛蓝 | ✔ | 部分：`--accent-rule` 与今日环按 45% 混入 affil |
| `--focus` | 焦点环 | 2px accent 环 | 随主题 accent | ✘（焦点色不随阵营漂移——可访问性锚点必须稳定） |
| `--game-badge` | 游戏标识色（GAMES.color） | —— | ✔（#4a90e2/#9d90ff/#ff6b6b/#ff8cc8） | ✘ |
| `--affil-key / accent / deep` | 归属三色 | 未注入→回落到主题 accent | —— | ✔ |
| `--affil-texture` | 低对比纹理 | 主题基础纹理 | ✔ 纹理家族按游戏图形气质 | ✔ 色相随 key |
| `--fx-strength` | 效果强度 0/0.5/1 | 0 中性 | 0.5 单游戏聚焦 | 1 选中角色 |

### 四个具体示例（改什么 / 不改什么）

| 原神·蒙德 `genshin-mondstadt`（key #5eb3d6 / accent #74c2a8 / deep #2d5a6b，ink=3） | 顶栏+日历 2px 色条混入风车蓝→蒲公英绿；今日环 mix 25% key；侧栏当前游戏接缝色=key；效果层=顶部径向微光 rgba(key,7%)；详情 header 沿用游戏色 | 暖褐表面阶梯、四级墨色、圆角/间距/字号、7 列网格、焦点环靛蓝 |
| 原神·璃月 `genshin-liyue`（key #d4a553 / accent #c8704a / deep #3d3027） | 同上四条边光换为琉璃金→丹砂红；效果层微光转暖金。与蒙德的差异只存在于边光色相——表面不动，所以「换了归属但没换产品」 | 同上 |

| 星铁 fallback `hsr-other`（key #4a5fd9 / accent #8ab4f8 / deep #0c1020） | 游戏级星海蓝边光 + 星点纹理（28px 点阵，opacity .32 沿用既有值）；**不虚构星球/阵营细分**；tagline「开拓群星之海」仅用于详情归属行展示 | 同上一切结构项 |

### 点击角色后的时间线（motionEnabled=true）

| t | 事件 |
|---|---|
| 0ms | pointerup → `setSelectedCharacter`；`resolveAffiliation` 同步求值；详情弹窗开始入场（160ms scrim + 200ms panel） |
| +1 帧 | `data-theme` / `data-affiliation` / `--affil-*` 落到 `.app`；已注册的自定义属性（`@property <color>`）开始 240ms 插值：色条、今日环、接缝、纹理层 opacity 同步过渡 |
| 0–240ms | 唯一在动的区域：四条边光 + 弹窗入场。网格、侧栏、工具条零位移 |
| 240ms | 静止。无循环动画残留 |
| 关闭弹窗 | useTheme 回落规则（follow-neutral→neutral；follow-character→lastBrowsedGame 保持染色）；边光 240ms 退去 |
| 连续快速点击 | token 更新是幂等属性改写，CSS transition 自动重定向（从当前插值点转向新值），无队列、无堆积；弹窗已开时只换内容不重放入场动画 |

### 缺失与退化

| 场景 | 处理 |
|---|---|
| 阵营未知（region 空/不识别） | `resolveGenshinAffiliation`→`genshin-other`、zzz→`zzz-other`、星铁/崩坏3→各自 `-other` 兜底（现有两级兜底链，不新增） |
| 缺立绘 | 详情回落纯色布局（G 节）；工作区边光不受影响（边光不依赖立绘） |
| 亮色对比不足 | affil key 作文本底时必须过 `contrast.ts` APCA 门槛（body≥75）；不过关的 key 降级为纯装饰边光，文字改用主题 accent。此规则落成单测，新阵营色入库即校验 |
| `motionEnabled=false` 或 `prefers-reduced-motion` | 全部时长 token 置 1ms（现有机制）；边光瞬时到位；锚点环静态显示 2s 后移除；弹窗无 scale 只有出现/消失。**边光系统的静态版本 = 最终状态本身**，不存在「没有动画就少了信息」 |

### 强度选择：平衡（静态主题 + 一次性 240ms 局部过渡）

- 不选「克制」：完全静态无法交付契约 4.3 要求的「这是不同归属」的点击反馈。
- 不选「强表现」：粒子/光效没有真实素材预算（阵营 bg 全为 null），只能靠程序化效果填充，那是装饰不是语义；且 42 格网格旁的持续动画直接违反性能底线 5.4。

## I. 视觉系统

### 色彩策略（生成与约束规则，不穷举阵营色）

1. **亮度骨架不动**：5 套主题共用同一 6~9 L* 台阶（theme.css 既有资产），阵营不改亮度只改边光色相——这是「看起来像同一产品」的根基。
2. **三色用途钉死**：key=边光主色（色条/环/接缝）；accent=边光辅色（渐变尾端/悬停偏移）；deep=仅用于详情 scrim 与效果层渐隐尾。任何新阵营入库必须提供三色且标注来源（现有 `source` 字段纪律）。
3. **游戏标识色**（GAMES.color）与 affil key 是两套系统：前者是 ≤24px 的身份标记（指示条/头像环/徽章），后者是边光。同屏出现时互不混用。
4. **约束**：正文永用墨色；强调色文本（accent-ink 压 accent）仅用于今日徽标、选中 chip、主按钮三处；大面积填充（>32px 高）禁止使用饱和度 >85% 的色值。

### 排版 / 间距 / 形状 / 图标

| 项 | 规则 |
|---|---|
| 字号阶梯 | 沿用 1.2 递比：micro 11 / xs 12 / sm 13 / base 15 / md 18 / lg 22 / xl 28；日期号 13 tnum；周条目名 13；侧栏组标签 11 + 0.08em 字距 |
| 行高 | 标题 1.15，正文 1.55，网格内文本 1.2 |
| 间距 | 4pt 阶梯（4/8/12/16/20/24/32/40/48）；工具条组间 12，组内 4；侧栏段间 20 |
| 圆角 | 容器 16 / 格子与输入 12 / 控件托盘 9 / 托盘内项 6（阶梯差 ≥3px，杜绝「圆角套圆角」同值模糊） |
| 边框 | 暗底亮边（`--line` 系）；**格子零边框**（填色表达状态）；全页边框总量控制：容器 1 圈 + 今日 1 环 + 幽灵格 1 虚线，其余靠填色 |
| 阴影 | 三级沿用；工作区内不用阴影分层（靠表面台阶），阴影只给弹窗/底单/Popover 三个浮层 |
| 图标 | 线性单色 1.5px，尺寸 16/20 两档；图标钮必须配 aria-label；语义状态（收藏/错误）图标+文字同行 |

### 反噪声三律

1. **同屏最多两级带框表面**：L1 日历容器/侧栏一级，浮层（弹窗/底单/popover）一级。格子、工具条、条目都不是独立卡片。
2. **填色优先于边框，留白优先于填色**：空日子=留白，有日子=填色，今天=填色+环。
3. **角色图片是唯一具象内容**：头像在格内（密度层），立绘在详情（情绪层）。工作区表面禁止任何图片/插画/渐变球。

## M. 风险与取舍

| # | 风险 | 控制措施 |
|---|---|---|
| 1 | uiCss.test.js 与类名/声明值强耦合，重写必破 | 实现 PR 内同步更新测试；先立检查点；以 57 项基线为门槛 |
| 2 | 02-29 幽灵格使 2 月行数 +1，跨月切换页高跳动 | 仅在存在 02-29 角色时追加；页面级滚动吸收；不做逐格动画所以无中间态 |
| 3 | 绝区零荧光阵营（#8dff3d 类）对比不过关 | I.4 约束：neon 只做 ≤2px 边光；contrast.ts APCA 写成单测，新色入库即校验 |
| 4 | `@property` 过渡在旧内核不可用 | 降级=瞬时换色（与 reduced-motion 等价），无功能损失；不引入 JS 补间 |
| 5 | 头像全部外链（wiki/honeyhunter…），离线/被墙时满屏首字块 | 首字块本身是设计内状态（游戏色 15% 底）；lazy + 固定槽位防跳动；不引入本地图库 |
| 6 | 卡片模式容量化是新行为，21 人日（09-15）表现未经实测 | 实现阶段用真实 09-15 数据做验收用例（本提案原型以 08-18 五人日作代表样本预演） |
| 7 | 1024 断点双轨（CSS+matchMedia）状态不同步 | 断点变化时强制关闭底单、重置焦点；验证矩阵含 1024/1025 双视口（项目既有惯例） |

**最可能失败的地方**：卡片模式在 20+ 角色日的容量算法与 +N 交互——测容逻辑若有 1px 误差（现代码注释记录的 scale 抖动坑），会反复出现「头像消失又出现」。缓解：沿用 offsetWidth 实测 + 只在 ResizeObserver 回调里重算，悬停 transform 与测容解耦。

**主动放弃的视觉诱惑**：
1. 阵营背景图/立绘渗入网格底——bg 字段全为 null，任何图都是编造；且底图毁扫描。
2. 每格描边卡片化——42 个框=容器噪声巅峰，填色方案信息量相同噪声为零。
3. 常驻粒子/光斑——无素材语义支撑，纯装饰，违反 5.4 与 reduced-motion。
4. 每游戏换正文字体——扫描一致性优先；display 字体只留 h1 与详情名两处。
5. 渐变按钮/霓虹描边全套——强调面只留三处（今日徽标、选中 chip、主按钮），其余描边一律 --line。

## 附 O. 隔离原型验证记录（prototype/）

2026-08-17 用 `prototype/shoot.mjs` 一次批量跑完 10 个状态（1440×900 中性/liyue/hares/liyue+弹窗/周视图；768×1024 中性/liyue；390×844 中性/hares；360×800 中性），探针硬指标全部通过：

- **零页面级横向溢出**（10/10，`scrollWidth === clientWidth`）；外部头像 0 失败（no-referrer + 首字回退生效）。
- 边光三件套（顶条 2px / 今日环 / fx 层）在 liyue、hares 两个阵营态按 token 生效；hares 态侧栏正确切到绝区零作用域筛选且原神行呈未选态。
- 移动端形态（侧栏移除、工具条两行、+N 溢出 chip）与 D 节纸面规则一致。

验证中发现并已处理的三个问题（如实记录）：

1. **详情立绘与文本争地**：首版 scrim 实心段只到 28%，splash 按 100% 高铺满时「稀有度/武器/编辑」压在画上。最终原型：scrim 实心段到 46%（= 信息列右缘），立绘 `background-size: auto 140%` + 向左钉住裁切，人物落到右半非文本区。两条数值回写为实现期 CharacterDialog 的对比验收线。
2. **移动端周视图规范缺失**：首版 D/E 节未写明 ≤1024px 周视图形态 → 已补「纵向日清单」规则（D、E 两节），原型同规则实现。
3. **token 作用域**：弹窗挂载点若落在 token 作用域外（原型首版 `#modalRoot` 在 `.app` 外），`--surface/--line` 全丢、弹窗变透明。**实现注意**：生产 theme.css 的游戏主题挂在 `.app` 的 `data-theme` 上，任何 portal 到 `body` 的浮层（现 DayPanel 即如此）只能拿到 `:root` 中性值——实现期要么把浮层挂回 `.app` 内，要么给 portal 节点重注入 `data-theme`。
