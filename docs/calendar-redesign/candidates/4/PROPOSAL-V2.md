# MiHoYo 角色纪日簿重绘提案

匿名编号：**4**

原型：[`prototype-v2/index.html`](./prototype-v2/index.html)

## 1. 从用户任务开始

### 1.1 黑盒用户旅程

**旅程一：日常扫月**

1. 进入当前月份，先辨认今天、月内外日期和哪些日期有事件。
2. 通过角色名条快速判断当天是谁、属于哪个游戏；同日过多时进入当天完整名册。
3. 沿月份书脊前后翻月，或回到今天，时间位置始终可见。
4. 在月与周之间切换后，保持同一时间锚点；返回时仍落在原日期。

**旅程二：缩小范围**

1. 从底部命令区进入临时的范围模式。
2. 第一步选择游戏，第二步只在该游戏内选择属性、稀有度、分类或归属。
3. 在确认前看见当前范围摘要和活跃条件数量。
4. 应用后回到原月份；无结果保留条件并提供逐项撤销，无游戏则提供一键恢复。

**旅程三：找一个角色**

1. 打开全局搜索，输入中英文名、游戏、日期、属性、武器/命途或地区/阵营。
2. 名称命中优先，最多出现 8 条；键盘上下选择、回车定位、Esc 返回。
3. 选择结果后跳到正确月份、点亮所在日期，并进入该角色的归属章节。
4. 可继续查看详情，也可关闭上下文回到中性日历。

**旅程四：从日期到角色内容**

1. 点击某日角色名条，日期不离开原位置，顶部章节立刻变成该角色语境。
2. 点击同日空白区域或溢出数，打开当天完整名册，再选择单个角色。
3. 进入全屏详情，查看日期语义、完整实装日期、属性与归属。
4. 可切为仅看立绘、收藏、导出单角色 ICS 或进入编辑；关闭后返回原月份与选中日期。

**旅程五：维护与交换数据**

1. 从低频档案入口选择添加/编辑、JSON 导入、导出或更新。
2. 添加/编辑先录字段，再处理 URL/本地图片与预览；JSON 先解析和预检，再确认写入。
3. 更新过程持续显示进度、结果和最后更新时间；导出无有效事件时给出明确失败原因。
4. 完成或取消后返回原时间位置，不打断日常浏览状态。

### 1.3 五个低保真缩略方案

#### 方案 A：无边界月历长卷（最终）

```text
┌书┬──────────────────────────────────────┐
│脊│  月份章节：标题 / 角色 / 归属图案       │
│↑├───┬───┬───┬───┬───┬───┬───┤
│08│ 日│ 一│ 二│ 三│ 四│ 五│ 六│
│↓├───┼───┼───┼───┼───┼───┼───┤
│今│  日期线 + 角色名条，直接铺满画布         │
│  │                                           │
│  │       [ 搜索 | 范围 | 月周 | 密度 | 档案 ]│
└──┴──────────────────────────────────────┘
```

- 核心假设：保留 7 列熟悉拓扑，但去掉“容器”，让时间像一本持续翻动的索引册。
- 最强优势：月扫效率不牺牲，灰度轮廓仍有书脊、长卷和底部命令区三个清晰地标。
- 最大风险：章节区与命令坞会占用日历垂直空间。
- 与常规骨架的差异：左缘只负责时间翻页，不常驻筛选；日期直接铺在画布上，没有右侧大日历卡。

#### 方案 B：周带剧场

```text
┌────────────────────────────────────────┐
│ 08 / 2026       当前角色舞台            │
├────────────────────────────────────────┤
│ WEEK 1 ━ 角色 ━━━━━━━ 日期节点 ━━━━━━━ │
│ WEEK 2 ━━━━━ 角色 ━━━ 日期节点 ━━━━━━━ │
│ WEEK 3 ━ 角色 ━ 角色 ━━━━━ 今天 ━━━━━━ │
│ WEEK 4 ━━━━━━━ 角色 ━━━━━━━━━━━━━━━━━━ │
│ WEEK 5 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
└────临时范围轨──────────────────────────┘
```

- 核心假设：用户更关心有事件的周，而非空日期。
- 最强优势：角色事件成为真正主角，同周事件比较很快。
- 最大风险：星期列被弱化，找“某月某日”比标准月拓扑慢。
- 与常规骨架的差异：没有日格卡片和左右分栏，整月由五至六条横向时间带构成。

#### 方案 C：日期星图

```text
┌──────────── 月份坐标场 ────────────────┐
│  ·01   ·02   ●03   ·04   ·05   ●06    │
│  ·09   ◎10   ·11   ·12   ●13   ·14    │
│              角色轨迹线                 │
│                  ╲  [角色切片]          │
├────────────────────────────────────────┤
│ 选中日的角色序列 / 归属坐标 / 操作       │
└────────────────────────────────────────┘
```

- 核心假设：月份首先是一张“哪里有事件”的密度地图，精确信息按需展开。
- 最强优势：极强的整体记忆点，稀疏月份一眼可见。
- 最大风险：点阵需要二次操作才能读角色名，违背高频扫描任务。
- 与常规骨架的差异：日期是坐标点而非小卡片，角色沿事件轨迹进入底部序列。

#### 方案 D：日期 × 角色双轴名册

```text
┌──────┬ 01 02 03 04 05 06 07 ... 31 ───┐
│原神  │        安柏票据 →                │
│星铁  │               布洛妮娅票据 →     │
│绝区零│    露西票据 →                     │
│崩坏3 │                  四人合并票据 →   │
├──────┴─────────────────────────────────┤
│ 选择一行后展开该游戏的二级范围            │
└────────────────────────────────────────┘
```

- 核心假设：跨游戏比较比星期拓扑更重要。
- 最强优势：来源游戏和事件数量非常清楚，筛选可以直接作用于行。
- 最大风险：31 列天然依赖横向滚动，移动端无法同时保证日期和角色可读。
- 与常规骨架的差异：横轴是整月日期、纵轴是游戏/角色，而非星期网格与侧筛选。

#### 方案 E：逐周翻页册

```text
┌────────── 本月缩略索引 ────────────────┐
│ 01 02 03 ... 31   [第 3 周]              │
├────────────────┬───────────────────────┤
│ 周日—周三       │ 周四—周六              │
│ 日期与大幅角色  │ 日期与角色文字           │
│                 │                        │
└─────────── 翻页 / 返回月索引 ───────────┘
```

- 核心假设：内容沉浸感可以通过一次只看一周获得，而整月只承担定位。
- 最强优势：人物立绘与日期关系最有编辑感，详情可直接在跨页中展开。
- 最大风险：扫完整月份需要多次翻页，重复使用效率不足。
- 与常规骨架的差异：主视图是书籍跨页，月份只作为缩略索引，不存在顶栏、侧筛选和日历卡组合。

### 1.4 选择与淘汰

选择方案 A，因为它是唯一同时满足“7 列月份扫描”“显著新轮廓”“移动端不横滚”和“角色内容可见”的方向。

- 淘汰 B：周带对事件很友好，但削弱星期与日期的固定空间记忆。
- 淘汰 C：星图辨识度最高，却让每次读角色名都增加一次操作。
- 淘汰 D：双轴名册在 31 日与窄屏之间存在结构性冲突。
- 淘汰 E：立绘表现强，但扫月必须翻页，不适合高频工具。

## 2. 最终方向与三个标志性机制

### 2.1 一句话机制

- **结构性标志：**月份书脊固定在左缘，七列日期无外框铺满纸面，所有全局命令从底部黑色装订条按需展开。
- **内容性标志：**每个角色事件是一张贴在日期基线上的“演员名条”，方形头像像邮票，名字、游戏与属性像演职员表。
- **上下文标志：**角色归属把顶部变为一次“章节换版”，同时改变人像裁切、图案节奏、文字方向和材质组织，而非只换主色。

### 2.2 五种状态中的可见表现

| 状态 | 结构性标志 | 内容性标志 | 上下文标志 |
|---|---|---|---|
| 中性 | 黑色月份书脊、灰白长卷、底部装订条 | 四游戏角色名条混排，角标提示有事件 | 巨型月份压印、折页缺口、无角色人像 |
| 原神·蒙德 | 日期结构完全不动，选中日期出现实线框 | 安柏名条与日期 08/10 对齐 | 椭圆拱窗、三道风带曲线、横向圆头归属章、宋体斜章名 |
| 原神·璃月 | 日期结构完全不动，08/26 被定位 | 凝光名条仍使用相同内容语法 | 阶梯式人像窗、方印套印、竖向契约章；窄屏退为横向印章 |
| 绝区零·维多利亚家政 | 日期结构完全不动，命令意义不变 | 艾莲内容仍是头像邮票 + 名条 | 切角服务票、棋盘格、斜向工单线、无衬线大写标题与紫金制服材质 |
| 星铁游戏级 fallback | 日期结构完全不动，角色按实装日期定位 | 名条明确“星铁”与命途 | 站点线路、六角车窗、胶囊式游戏章，并明确 `GAME-LEVEL`，不虚构细阵营 |

### 2.3 Theme Profile 与场景图层

本修订采用 `ThemeProfile + scene layers`，不是从立绘实时取色，也不是给每个角色复制一套 CSS。每个 profile 只提供：`baseStart / baseMid / baseEnd` 基础渐变、`haloPrimary / haloSecondary` 光源、`stageDeep / stageBorder` 舞台层、`surface / surfaceBorder` 月历表面、`accent`、生日/实装事件色，以及普通工作区和全屏详情的强度。

场景顺序固定为：全局对角渐变 → 一个主径向光晕 → 一个低透明辅助光源 → 左侧立绘裁切 → 立绘自上而下压暗 → 半透明深色月历表面 → 头像、事件点和边框。网格尺寸、日期位置、控件位置和名条规则不随 profile 改变。

原型已经提供 `neutral`、`genshin`、`genshin-sumeru`、`hsr`、`zzz`、`honkai3` 六个 profile；顶部新增真实须弥角色珐露珊样本。中性状态采用阿蕾奇诺概念图的深靛基准，须弥采用深青绿 + 薄荷光晕，星铁和崩坏3只有游戏级 fallback。角色图片只作为舞台内容，不参与运行时像素取色。

## 3. 信息架构

### 3.1 按任务频率分层

| 频率 | 任务 | 入口 | 返回路径 |
|---|---|---|---|
| 高频 | 前后月/周、今天、扫日期 | 左缘月份书脊；日期长卷 | 原位完成，不离开时间画布 |
| 高频 | 搜索、筛选、月周、密度 | 底部命令坞 | 命令页向下收合，保持月、日和选中角色 |
| 高频 | 当天全部角色、角色上下文 | 日期整格、名条、溢出数 | 当天名册从右退出；上下文可回中性 |
| 中频 | 生日/实装语义、详情、仅看立绘、收藏、单角色 ICS | 章节日期章；角色章节中的“查看角色” | 全屏卷宗左上“返回月历”，回到原定位 |
| 中频 | 周起始日、立绘动效与背景偏好 | 档案入口中的显示偏好 | 收合档案页，偏好即时生效并持久化 |
| 低频 | 添加/编辑、JSON 导入、全量导出、数据更新 | 底部“更多”进入档案折页 | 完成/取消均回原时间状态；错误保留输入 |

功能没有按旧控件清单逐项安置，而是重组为三种工作模式：**浏览时间、限定范围、维护档案**。浏览始终留在长卷；搜索和筛选是临时聚焦；维护被放到最低频的档案层。

### 3.2 黑盒能力映射

| 能力 | 新组织方式 |
|---|---|
| 完整月历与 7 列拓扑 | 无外框 7×6 日期长卷；补位日期灰底、今天黑底数字、事件角折 |
| 周视图 | 桌面为七条并列日带；移动为七段纵向日带，不缩成细列 |
| 前后期、今天、年月跳转 | 书脊上下翻页与“今天”；点击书脊月份打开年月索引 |
| 周日起始 / 周一起始 | 显示偏好中切换，列标题和月首偏移同时更新 |
| 生日 / 实装 | 章节中的日期章切换；星铁固定实装，崩坏3缺失实装时明确回落生日 |
| 非闰年 2 月 29 日 | 2 月 28 日后附斜纹“2/29·本年无此日”例外票，不伪装成 2/28；ICS 仍按 2/29 重复 |
| 三种密度 | 卡片：脸 + 名 + 游戏属性；头像：方形邮票；紧凑：纯文字名条 |

| 四游戏多选和独立二级条件 | 两步范围模式；每个游戏保留自己的条件状态，切换游戏不会互相污染 |
| 全局搜索 | 从命令坞展开，检索不受当前范围影响；定位后进入角色章节 |
| 角色详情与仅看立绘 | 全屏双域卷宗；仅看立绘把资料域收起，而非另开居中弹窗 |
| 收藏与单角色 ICS | 详情卷宗的直接动作；收藏状态同时进入范围条件 |
| 添加/编辑与图片 | 档案折页中的分步表单：字段 → 图片 URL/本地上传 → 预览 → 校验 |
| JSON / ICS 导入导出 | JSON 先解析预检；导出按格式分流，无有效事件时保留范围并解释原因 |

## 4. 关键视图规范

### 月视图

日期线而不是日期卡构成 7×6 网格。每格左上固定两位日号；补位日降低对比，有事件的右上角做纸张折角。名条宽度受格内约束，卡片密度最多两条、头像最多五枚、紧凑最多四条，其余进入当天名册。

### 周视图

桌面把七天变成七条等宽“日带”，日号成为大号索引，角色名条纵向排列。移动端彻底重排为七段纵向列表，每段左侧固定日号，右侧放角色，不让七个窄列承载详情。

### 筛选过程

范围页从底部装订条展开并遮住下半月，但上方仍露出月份和时间位置。步骤 01 选择游戏，步骤 02 在当前游戏内缩小特征；底部固定显示清除、范围摘要和“查看结果”。切换游戏时各自条件不被重置。

### 搜索与定位

搜索页同样从底部展开，但高度更短。输入框之后最多 8 条，名称匹配优先；每条显示角色、游戏、属性/归属和实际日历日期。选择后自动切月、选择日期、加载上下文章节。键盘支持 `ArrowUp`、`ArrowDown`、`Enter`、`Escape`。

### 当天多角色

整格或 `+N` 打开右侧窄名册，按游戏显示方形头像、姓名、属性和分类。选择角色后名册退出、日历仍在，章节更新。8 月 18 日样本验证了同日多角色与回退数据。

### 角色详情与仅看立绘

详情是占满视口的卷宗场景：左域只承担立绘与归属材料，右域是白底结构化资料；信息不压在立绘上。仅看立绘时右域完全收起，左上保留“返回详情”。桌面和平板双域并列，手机上下分域；关闭和返回永远位于可视区域。

### 添加/编辑与 JSON 导入

- 添加/编辑：基础字段、日期语义字段、游戏专属字段分段；图片 URL 与本地上传共享预览区；校验错误贴近字段。
- JSON：接受单对象或数组，先显示解析数、重复 ID、无效日期和将覆盖字段，再允许确认。
- 原型只演示入口、表单结构和真实 JSON 解析反馈，不假装写入生产数据。

### 状态

| 状态 | 表现与恢复 |
|---|---|
| 无游戏 | 日期长卷被 `∅` 索引覆盖；“恢复全部游戏”是唯一主动作 |
| 无筛选结果 | 保留条件与月份，列出活跃条件并提供逐个撤销；搜索仍是全局的 |
| 无图片 / 加载失败 | 人像窗显示稳定日期字样或姓名首字，详情继续显示全部文字字段 |
| 同步中 | 档案折页出现确定/不确定进度线、已处理数与取消，不阻塞浏览 |
| 同步完成 / 部分失败 | 显示新增、更新、跳过数和最后更新时间，可展开错误清单 |
| 导出失败 | 明确“没有有效日期”或浏览器拒绝下载，并提供返回检查范围 |
| 日期缺失 | 名条不进入错误日期；维护页给出缺失原因，不让某游戏静默清空 |

## 5. 响应式策略

| 视口 | 结构 |
|---|---|
| 1440×900 | 88px 书脊；184px 章节；七列长卷占余高；620px 底部命令坞；详情 46/54 双域 |
| 1024×768 | 72px 书脊；章节信息压缩为标题区 + 330px 人像章；次要统计隐藏；命令坞保留文字 |
| 768×1024 | 58px 书脊；208px 章节；归属章避免窄竖排；七列获得更高日格；详情约 45/55 双域 |
| 390×844 | 44px 书脊；172px 章节；上下文样本横向滚动但页面不滚；命令坞只显示图标；详情上下 43/57 |
| 360×800 | 保持 44px 书脊；七列每列约 44px；名条只保留头像和截断名；星铁线路与人像章仍可辨；命令坞五等分 |

补充规则：

- 7 列始终使用 `repeat(7, minmax(0, 1fr))`，所有文字容器 `min-width: 0`，图片绝不参与列宽计算。
- 长角色名、游戏名和阵营名先单行省略；详情中允许任意位置换行，不减小全局字号。
- 移动卡片虽紧凑，但整个有事件日期格可点击、可聚焦并支持 Enter/Space，避免只依赖 23px 名条。
- 键盘弹起时搜索/编辑页使用动态视口高度；输入区固定在顶部、结果区独立滚动，当前选择滚入视野。
- 所有超高浮层把标题/关闭和底部确认固定，只有中间内容滚动；滚动锁只作用于底层长卷。
- 月视图不做页面级横向滚动；上下文样本自身可以短距离横向浏览，不改变日历宽度。

## 6. Context Theme System

### 6.1 概念数据流

```text
selectedCharacter
  → resolveAffiliation(character)
  → { game, id, name, nameEn, tagline, key, accent, deep, level }
  → normalizeContext(已知归属 / 游戏级 fallback / unknown)
  → chapterGrammar(game, affiliation.id)
       ├─ portraitMask       人像窗裁切
       ├─ rhythmPattern      风带 / 方印 / 棋格 / 线路
       ├─ typeArrangement    宋体斜章 / 竖契约 / 无衬线工单 / 线路编号
       └─ materialRule       纸、印、票据、车窗
  → semanticColorTokens(key, accent, deep)
  → stableCalendar + one-shot chapter feedback
```

结构和操作含义从不进入主题分支；主题只改变章节语法、选中日期的局部反馈和详情艺术域。

### 6.2 归属规则

- 蒙德：拱形人像窗、三道风带、圆头横章；颜色只辅助自由与空气感。
- 璃月：阶梯窗、同心方印、契约字向；即使去色仍能靠方印与竖向组织识别。
- 维多利亚家政：切角服务票、棋盘格、斜工单线和大写无衬线；不是把蒙德章换成紫色。
- 星铁 fallback：显示游戏级线路和站点，明确 `GAME-LEVEL ROUTE`，不从角色字段猜测阵营。
- 崩坏3 fallback：使用游戏级战术档案语法，保持生日回落说明，不虚构组织映射。

### 6.3 边界与动效

- 连续快速切换：采用 latest-wins；旧图片解码和旧 520ms 形变被取消，颜色 180ms 内稳定，日历不重排。
- 阵营未知：保留该游戏基础语法，归属章显示真实游戏名和“归属待补充”，不落到其他游戏世界观。
- 无立绘：保留人像窗形状和章节图案，窗内显示姓名首字/月份字样；信息不依赖图像。
- `motionEnabled=false` 或 `prefers-reduced-motion`：所有颜色、裁切和图案同步静态替换，不播放位移、淡入和形变。
- 截图全部使用 `motion=off`，证明无动画时阵营仍通过拱窗、方印、服务票和线路图区分。

## 7. 设计系统

### 7.1 基础 token

| 类别 | token / 数值 | 用途 |
|---|---|---|
| 中性颜色 | 深靛起点 `#080B17`、中段 `#15162B`、终点 `#24203C`、月历表面 `#111426` | 全局渐变、月历面板、书脊和日期线 |
| 功能颜色 | 生日珊瑚 `#FF897D`、实装薄荷 `#6DC2A9`、中性强调 `#D8C7FF` | 事件折角、生日/实装、主动作和命令装订条 |
| 上下文颜色 | `haloPrimary / haloSecondary / stageBorder / surfaceBorder` 来自 profile；`key / accent / deep` 来自 affiliation | 光晕、舞台边框、局部表面和详情艺术域 |
| 间距 | 5 / 7 / 12 / 18 / 28 / 44 | 名条内距到书脊/触控尺度 |
| 形状 | 0 / 4 / 7px；归属特例用 `clip-path` | 日期无圆角，控件小圆角，人像窗承载语义形状 |
| 动效 | Fast 180ms、Chapter 520ms | 状态反馈与章节换版；无持续背景动画 |

### 7.2 规则

- 排版：中文章节名用宋体语气，操作和元数据用系统黑体，日期数字用窄体无衬线；三者对应“人物、操作、时间”。
- 图片：月历只用方形内容头像；章节和详情使用真实透明立绘，不用无关氛围图，也不把立绘模糊成文字背景。
- 图标：箭头、搜索、网格、密度、下载等使用熟悉符号并配 `aria-label`/tooltip；生产实现可替换为统一图标集。
- 材质：纸张线、邮票、装订、工单和章节印都是“年度角色档案”的产品语义，不铺满每个表面。
- 性能：每次只有一个章节可能发生短动效；日格无持续粒子、滤镜或模糊动画；图片失败立即进入静态回退。

这套系统不是任意 SaaS 皮肤：月份书脊、角色演员名条、章节归属语法和全屏人物卷宗都直接来自“角色纪念日档案”，而非数据看板、营销卡片或通用表单。强主题只在全屏详情中进一步增强，普通月历保持中等强度，避免把每个日期格单独染色。

## 10. 自我反证

### 10.1 七项旧结构指纹

| # | 旧结构指纹 | 是否保留 | 证据 |
|---|---|---|---|
| 1 | 顶部一行标题、搜索、收藏和添加 | 否 | 顶部是内容章节；搜索在底部命令，收藏在详情，添加在档案层 |
| 2 | 左侧固定筛选，右侧日历 | 否 | 左缘仅是月份翻页书脊；筛选是临时底部两步模式；日历铺满主画布 |
| 3 | 大圆角深色日历容器 | 否 | 日期直接位于浅色画布，无外围卡片、圆角或深色包裹 |
| 4 | 视图与设置横排在日历容器顶部 | 否 | 命令固定在底部装订条，且日历没有容器顶部 |
| 5 | 深色日期小卡 + 圆头像簇 | 否 | 日期是线框纸面；角色是白色横名条与方形头像邮票 |
| 6 | 阵营主要靠顶部细色条、描边和轻换色 | 否 | 主要反馈是拱窗/阶梯窗/服务票/线路、图案节奏与字向；边色只是辅助 |
| 7 | 居中圆角详情弹窗，立绘作文字背景 | 否 | 详情占满视口，立绘与资料分域，信息不压在图片上 |

**完整保留：0 / 7。** 左缘时间书脊和底部命令条可能让人联想到导航，但它们不承担旧指纹中的常驻筛选或日历顶部工具条语义。

### 10.2 灰度并遮字后是否仍不同

是。截图 10 实际启用了灰度并遮掉章节、上下文、名条和命令文字。仍然可见的证据是：左侧窄书脊、上方非对称章节压印、无外框的整页 7×6 线框、横向邮票名条轮廓和底部黑色装订条；不存在“顶部控制行 + 左筛选 + 右圆角日历卡”的三段轮廓。

### 10.3 去掉阵营颜色后内容性标志是否成立

成立。角色仍由方形头像邮票、横向姓名位置、游戏/属性两层字级和 `+N` 当天名册入口表达。灰度审计图中这些票据轮廓依然直接区别于普通会议日历。

### 10.4 没有动画时是否仍不只靠换色

成立。全部正式截图均使用 `motion=off`：蒙德仍有椭圆拱窗和风带，璃月仍有阶梯窗和方印，维多利亚仍有切角服务票、棋盘格与工单斜线，星铁仍有站点线路和六角窗。

### 10.5 最大胆且最可能损害效率的设计

大胆点是 184/172px 的“章节换版”占据首屏高度。控制措施是可验证的：1440×900 仍同时显示 6 个完整周行；768×1024 与 390×844 仍显示完整 7×6；360×800 无横向滚动；月内事件始终在首屏。正式实现的验收阈值是所有目标视口完整显示星期头、至少 5.5 周与底部命令，若真实内容使其失败，章节高度降一级而不是压缩日格触控区。

### 10.6 被移动或分层、而非删除的功能

- 搜索从全局头部假设移动到临时定位模式。
- 筛选从常驻占宽移动到两步范围模式，并保留游戏隔离状态。
- 收藏入口从全局移动到角色详情，收藏筛选仍在范围模式。
- 添加、编辑、JSON、全量导出、同步和显示偏好被收进低频档案层。
- 月/周、密度和日期语义分别进入底部命令与章节日期章，没有删除。
- 当天多角色从日格溢出移动到右侧完整名册；角色详情再进入全屏卷宗。
- 立绘背景偏好、动效、周起始与持久化被放在显示偏好层，不占高频扫描空间。

## 11. 风险与验证

| 风险 | 控制 | 验证指标 |
|---|---|---|
| 章节区抢占日历空间 | 响应式高度分档，次要统计逐级隐藏 | 六周可读、无日格被命令坞遮挡 |
| 名条在 360px 过窄 | 名字省略、头像优先、整格进入当天名册 | 7 列无横滚；有事件日整格可触控/键盘进入 |
| 上下文图案抢角色注意 | 只限章节与详情艺术域，日历结构保持中性 | 灰度下日期线对比高于图案；日格无滤镜 |
| 快速切换图片闪烁 | latest-wins、解码后替换、稳定回退窗 | 连续点击五次不重排、不残留旧章 |
| 底部范围页遮住日期 | 上方保留月份与部分日期作为位置提示 | 关闭后滚动与选中位置完全恢复 |
| 低频能力被藏得太深 | “更多”始终在五等分命令坞中，档案首页直列四类任务 | 两步内到达添加、JSON、导出或同步 |
| 远程图片失败 | 方形首字回退与章节日期字回退 | 断网后日期、角色名、归属和详情字段仍完整 |

最终判断：此方向的差异首先由截图中的书脊、无边界长卷、角色名条、章节换版与全屏卷宗证明；文档只解释这些可见机制如何覆盖完整能力与退化路径。
