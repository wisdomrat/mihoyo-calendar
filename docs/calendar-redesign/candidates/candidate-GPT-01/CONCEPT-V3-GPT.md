## 视觉说明

- **一句话主张**：把角色生日与实装日做成一张持续发光的「记忆轨道」，月历是导航骨架，立绘是舞台主角。
- **前三秒视线**：先看左侧大幅角色和日期数字，再看右侧玻璃月格的事件亮点，最后看筛选胶囊与角色详情入口。
- **米哈游识别度**：使用真实角色立绘、中文角色名与游戏/地区标签；角色像内容卡一样有收藏价值，不依赖普通 SaaS 的卡片堆叠。
- **创意透镜转译**：收藏界面的精致比例 + 舞台式光晕。每个状态只移动一层「舞台色」，网格、字号和信息位置保持稳定。
- **版式骨架**：左 34% 为沉浸式主角幅面，右 66% 为可扫描月格；详情页把立绘扩展到右侧 55%，时间信号留在左侧。
- **字体层级**：Arial / Microsoft YaHei 作为系统无衬线；月份 44–48px、角色名 52–94px、日期 15–76px，英文小标签 10–12px 大写字距。
- **色彩分工**：深靛黑为中性色底；珍珠白承载日期与标题；薄荷青表示原神/须弥过滤与匹配事件；珊瑚橙表示生日/选中；紫色负责默认舞台光。
- **角色图像**：使用真实项目 JSON 中的 `portrait` 素材，本地保存为 webp；桌面端大裁切，头像仅在有事件的日期里出现，移动端只保留一个主角幅面。
- **月视图表达**：有事件＝彩色点；今天＝浅色胶囊；选中＝高亮边框/反色胶囊；多角色＝同一日期保留头像 + 色点，不再增加密集文本。
- **上下文变化原则**：选中游戏/地区时只替换主角、光晕、标签和匹配点；网格尺寸、日期位置、返回路径必须稳定，避免筛选造成界面跳变。
- **材质与动效边界**：玻璃只用于月格容器和低频筛选；渐变/模糊只集中在背景舞台；霓虹仅作为事件信号。去掉动效和大部分颜色后，仍靠比例、白字层级、日期网格和角色裁切成立。

## 最大风险

左侧大幅立绘可能压缩月格的可用宽度；正式实现时需维持日期字号与事件点的最低可读性。背景光晕若在每个组件重复会退化为赛博模板，必须限制在页面舞台层；地区色也不能改变文字对比度。移动端不应继续缩放桌面分栏，而应保留「主角 → 月格 → 下一事件」三段顺序。
