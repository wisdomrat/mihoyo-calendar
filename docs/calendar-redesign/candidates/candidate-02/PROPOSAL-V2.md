## 0. 一句话概念

日历不是被容器装着的控件，而是一面**工作台墙面**：7 列月历直接画在纸墨表面上，事件用**刻度**标记；点某一天，右缘滑出一块**纪念日立板**（大立绘 + 阵营名牌 + 当日全名单）；点角色，整屏进入**角色一幕**。所有命令收进底部**命令坞**，顶部只留一条**时间坐标缘**。阵营上下文不靠色条，而靠**表面材质**（纹理 / 图样带 / 水印字排 / 明暗表面）表达。

### 3. 五个缩略线框（结构差异，非按钮搬家）

```

├──────┬───────────────┤   ├──────────────────────┤   │ 月历(原色) │ 月历    │

│ 常驻 │  头像簇小卡     │   │ 事件为竖向书签条      │   │ 绝区零桌面 │ 崩坏3   │
└──────┴───────────────┘   └──────────────────────┘   └───────────┴─────────┘

┌──────────────────────┐   ┌──────────────────────┐

│   当月主角大立绘舞台    │   │ ┌─┬─┬─┬─┬─┬─┬─┐    │
│   聚光+其余日期缩为票根 │   │ │‖│ │ │‖│ │ │ │ 刻度墙面（无容器）│
├──────────────────────┤   │ └─┴─┴─┴─┴─┴─┴─┘    │
│ 日期票根横向滚动带      │   │              ▐立板▌ │ ← 右缘滑出
│ 底部演出控制条         │   │ [游戏][筛选][搜索][密度][桌面][＋] │ ← 命令坞
└──────────────────────┘   └──────────────────────┘
```

每个方案的核心假设 / 最强优势 / 最大风险 / 为何不同于"顶栏+侧栏+日历卡"：

- **A 指挥台**：假设"效率来自常驻控件"。优势：零学习成本。风险：与旧结构同构，阵营只能靠换色。不同点：其实它*就是*常规结构——作为对照组保留。
- **B 时间长卷**：假设"一年是一条河，扫描=漂流"。优势：跨年连续、事件密度可视化。风险：丢失 7 列月拓扑（brief 3.1 要求保留）、横向滚动在移动端致命、定位某月慢。不同点：无顶栏无侧栏，时间轴即导航。
- **C 四游戏桌面**：假设"用户按游戏分心"。优势：游戏语义最强，四套材质并置。风险：每格只有 1/4 宽，月历扫描（任务 1）被牺牲；跨游戏同一天无法一眼见；信息密度翻倍但视口不变。不同点：结构是 2×2 世界墙，无统一日历容器。
- **D 舞台聚光**：假设"日历是演出，今天是主角"。优势：内容性极强，角色即视觉中心。风险：月度扫描效率差（非主角日期被压缩成票根）、每天换主角造成布局跳动、与"可反复使用的工具"定位冲突。不同点：无网格主体，舞台+票根带。
- **E 纪念日墙**：假设"扫描要安静、进入要隆重"——墙面负责快扫（刻度），立板/一幕负责慢看（立绘与名单）。优势：7 列拓扑保留且无容器噪音；内容标志（刻度）与上下文标志（材质）都成立；命令分层清晰。风险：纸质表面若无材质层会显得"文具 SaaS"——用阵营材质四层解决。

### 4. 淘汰理由

- 淘汰 A：与旧结构同构，过不了 6.2 指纹门槛，阵营表达必然退化为换色。
- 淘汰 B：违反"月视图保留 7 列星期拓扑"的硬能力，移动端横向滚动是硬性淘汰项。
- 淘汰 C：把最高频任务（整月扫描）切成四块，效率倒退；四套材质并置也稀释了"上下文跟随选择"的语义。
- 淘汰 D：布局随"主角"跳动，触控目标不稳定（5.2），且把工具做成了营销页。
- 选 E：唯一同时满足 7 列拓扑、无容器、内容标志、上下文材质、命令分层的方案。

## 阶段二 · 定义

### A. 三个标志性机制（一句话 + 四态表现）

1. **结构性标志**：日历画在无容器墙面上，顶部只有时间坐标缘、底部只有命令坞——灰度轮廓里没有顶栏、没有左栏、没有圆角日历卡。
2. **内容性标志**：事件刻度——每 1 位角色 = 1 道刻线（>5 时第 6 道为封顶刻），普通日历没有这种"人数即刻度"的记号。
3. **上下文标志**：表面材质——阵营切换同时改变墙面纹理、立板图样带、水印字排（衬线斜体 vs 900 黑体）、环境光位置与明暗表面，颜色只是其中一层。

| 状态 | 结构 | 内容（刻度） | 上下文（材质） |
|---|---|---|---|
| 中性 | 墙面=素纸，无水印 | 墨色刻线 | 无纹理、无图样带、衬线水印隐藏 |
| 原神·璃月 | 同上 | 刻线染岩金色 | 岩壁颗粒+水平层理纹理、左下环境光、立板"岩层"图样带、衬线水印"璃月/Liyue" |
| 原神·蒙德 | 同上 | 刻线染风蓝色 | 斜向风纹、右上环境光、立板"风线"图样带、斜体衬线水印 |
| 绝区零·狡兔屋 | 同上 | 刻线染荧光绿 | 信号点阵纹理、底部霓虹渐变、立板 45° 危险条纹带、**900 黑体水印与阵营名**（字排也换） |
| 星铁 fallback | 同上 | 刻线染星蓝 | 星轨斜线+稀疏星点、立板点阵带、名牌附"游戏级主题·阵营待细分"虚线签 |

### B. 信息架构（频率分层，非组件找位）

| 层 | 频率 | 任务 | 入口 | 返回 |
|---|---|---|---|---|
| L0 墙 | 高 | 月扫描、翻月、回今天、切周/月、切语义 | 打开即达；时间缘 | — |
| L1 立板 | 高 | 当日全名单、逐日移动、收藏、进详情 | 点格/Enter | 收起立板/Esc |
| L2 一幕 | 中 | 角色详情、仅看立绘、单角色 ICS、编辑 | 立板/周列/搜索 | 返回名单/Esc |
| L3 坞+面板 | 中 | 游戏范围、二级筛选、搜索、密度 | 命令坞按钮（互斥升起） | 完成/Esc/点墙 |
| L4 维护 | 低 | 偏好、同步、导出、添加/编辑/导入 | 坞"桌面"/"＋" | 关闭面板 |

能力没有被删除，只被**分层**：搜索从顶栏降入坞（J4 不需要常驻输入框）；收藏从顶栏按钮变为立板行内♥与一幕动作（收藏是"对角色的态度"，不是全局视图）；添加/导出/同步收进维护层。

### C. 关键视图（原型均可交互到达）

- **月视图**：7 列；今天=红环+“今天”角标（不只靠颜色：有文字）；补位日降透明；有事件=刻度；溢出=封顶刻+立板全名单（不静默丢失）。
- **周视图**：7 根日柱名单（移动端改单列堆叠），行内游戏色点+语义标签+闰日标签。
- **筛选过程**：面板=过程（先选游戏→该游戏专属维度逐个点亮→计数实时 `288 → N 位`→完成/清除）；完成后范围以**筹码条**留在墙顶，可逐个移除。
- **搜索与定位**：`/` 或坞按钮；全库、名称优先、≤8、↑↓ Enter Esc；选中→跳月+开立板+进一幕。
- **当天多角色**：08-18 五人日——立板全名单+立绘领头+逐行收藏/进入。
- **详情与仅看立绘**：一幕左右分幕；"仅看立绘"隐去信息侧栏，浮出圆形退出钮；无立绘角色（崩坏3 多数）显示首字材质替身并明确说明。
- **添加/编辑 + JSON 导入**：表单含头像 URL+本地图片预览；导入接受单对象或数组，报"新增 x / 更新 y"，解析失败给错误行。
- **状态**：无游戏=空墙+四枚恢复按钮；安静月=“安静的一页”+清除/去八月；无图=替身；同步=进度行→成功/失败两路（失败有 toast）；导出无有效事件=toast 反馈。

### D. 响应式策略

| 视口 | 结构（非压缩桌面） |
|---|---|
| 1440×900 | 全幅墙；立板右滑 384px；一幕左右分幕 |
| 1024×768 | 立板收窄 340px；其余同桌面（7 列不变，格高自适应） |
| 768×1024 | 一幕改上下分幕（立绘上 42%）；立板 340px；坞换行 |
| 390×844 | 立板改**底部抽屉日单**（高 62%）；周视图改单列堆叠；密度卡档隐藏名字只留头像+刻度；命令坞两行 |
| 360×800 | 同上+**JS 强制 compact 密度**（刻度+×N 计数），缘坐标缩排；dev 条隐藏 |

7 列永不被撑宽：格内全部绝对定位+`min-width:0`+省略号；长阵营名在立板内换行、水印用 `white-space:pre` 固定两行。键盘弹起：面板 `max-height:72vh` 可滚动，关闭钮恒在面板头。

### E. Context Theme System

```
selectedCharacter / boardLead / pinnedDemo
        │  resolveContextAff()  优先级：一幕 > 立板 > 钉住 > 中性
        ▼
affiliation {id, game, ink, colors{key,accent,deep}, fallback?}
        ▼  applyTheme()（快速切换经 120ms 防抖，只落最终态）
html[data-aff][data-game][data-ink] + --aff-key/accent/deep
        ▼  CSS 材质四层
纹理(墙) · 图样带(立板) · 水印字排(字体/字重/斜体) · 环境光(位置) · 明暗表面(ink)
```

- **快速切换**：120ms 防抖 + 360ms 背景过渡；连点 dev 条只渲染最终材质，不排队闪烁。
- **阵营未知**：未映射地区落 `*-other`（提瓦特/新艾利都），数据不虚构更细映射。
- **游戏级 fallback**：hsr/honkai3 恒为 `*-other`，立板名牌附虚线签"游戏级主题·阵营待细分"。
- **无立绘**：一幕/立板用首字材质替身（衬线大字），并文字说明"暂无立绘"。
- **reduced-motion**：`prefers-reduced-motion` 全局去过渡；偏好"动效=关"加 `.nofx` 同等效果；材质是静态纹理，**无动画时阵营差异完整保留**。
- **阵营差异不只颜色**：见 A 表——璃月与蒙德纹理方向不同、稻妻竖纹+暗表面、绝区零点阵+黑体字排、星铁星轨线；灰度下仍可分辨（见阶段四 Q4 证据）。

### F. 设计系统（自建 token）

- 排版：展示=衬线（Georgia/Songti，用于坐标、阵营名、角色名——"纪念"的碑刻感）；UI=系统黑体。绝区零上下文把展示层**换成 900 黑体**（字排即阵营）。
- 颜色：纸 `#f2efe7` / 墨 `#23221d` 双阶；ink=1 阵营整面转深纸 `#16171c`。今天环 `#b3402e`（朱砂，非阵营色，避免混淆）。
- 间距 4px 基线；形状刻意反圆角容器：墙 0 / 筹码 3 / 坞 10。
- 动效：主题 360ms、面板 220ms、立板 260ms，单一缓动；全部可被 `.nofx`/媒体查询归零。
- 为何适合角色日历：纸墨+衬线=纪念日册页语义；刻度=人数记号；材质=阵营气质——三者都无法套用到普通 SaaS 日历。

## 原型与运行

- 路径：`prototype-v2/`（`index.html` + `style.css` + `app.js` + `js/data.js` + `data/characters.json`）。
- 运行：`cd prototype-v2 && python -m http.server 8765` → `http://localhost:8765/`（file:// 亦可，同步演示需 http）。
- `js/data.js` 由 `dev/gen-data.mjs` 自真实数据生成（288 角色、28 阵营）；`dev/shots.mjs` 为截图驱动。
- dev 条（左下"上下文演示"）是**演示辅助**，非设计组件：用于钉住任意阵营上下文供评审截图；正式交互中上下文跟随选择（可在桌面面板关闭跟随）。

## 阶段四 · 自我反证

**Q1 旧结构指纹保留了几项？** 0 项（门槛 <4）。
1. 顶行标题+搜索+收藏+添加：否——顶缘只有时间坐标与视图/语义段；搜索/添加在坞。
2. 左固定筛选栏：否——筛选是临时面板+底部坞。
3. 大圆角深色日历容器：否——墙面无容器；ink=1 深色是整面材质，不是"容器"。
4. 视图设置横排日历容器顶：否——视图/语义在时间缘右端（时间属性），密度是坞单钮，其余在维护面板，三者不组成"设置条"。
5. 深色小卡+圆头像排：否——格子是墙面划线区域，事件=刻度；卡档的 16px 头像行是密度增强而非容器卡，且非深色卡。
6. 阵营=细色条/描边/轻换色：否——材质四层。
7. 居中圆角弹窗+立绘背景压信息：否——一幕是全幅分幕，立绘与信息各占其幕，不互压。

**Q2 灰度+遮品牌后仍不同？** 是。证据：01/07 灰度轮廓为"细缘+满幅网格+底部坞"，无顶栏块、无左栏块、无圆角容器块；事件日为刻线记号而非填充卡。与"顶栏+左栏+右圆角卡"的灰度块状结构在区域分割上即不同（墙占满、坞在底）。

**Q3 去掉阵营颜色，内容性标志成立？** 成立。刻度=人数记号，中性态即刻见（01 图无阵营色仍有 ‖/‖‖‖ 记号）；立板/一幕的"领头立绘+名单"结构也不依赖颜色。

**Q4 无动画时阵营差异不只换色？** 是。材质层全部静态：璃月颗粒层理 vs 蒙德斜风纹 vs 绝区零点阵 vs 星铁星轨线，在 `nofx`（19 图）下纹理/图样带/字排差异完整；字排差异（衬线 vs 900 黑体）与颜色无关。

**Q5 最大胆设计最可能损害什么，如何控制？** 大胆点=无容器墙面+刻度。风险：刻度需要一次学习（"‖ 是什么"）。控制措施：刻度旁在卡档保留名字行、紧凑档保留 ×N 计数（双编码，不只靠记号）；点格即开立板全名单（记号永远可展开为名单）；今天/选中用环+文字双编码。可验证：01/07/09 三档截图均可见双编码。

**Q6 哪些功能被移动/分层而非删除？** 搜索（顶栏→坞+`/` 快捷键）；收藏（顶栏→立板行内♥+一幕动作+筛选面板"只看收藏"）；添加/导出/同步（顶栏→维护面板）；视图设置（容器顶条→时间缘右端+维护面板）。全部能力在原型可交互到达，见能力映射表。

## 风险

1. 纸墨+衬线若无材质层会显"文具 SaaS"——材质四层是命门，实现时需保证纹理对比度足够（当前 6-13% 混色，暗表面阵营已验证可读）。
2. 右滑立板在 1024 宽会暂遮第 7 列——接受（立板是临时层，Esc 即收）；≤720 已改底部抽屉。
3. 衬线展示字体跨平台回落（Windows SimSun / mac Songti）字重差异——水印与名牌已用 `clamp` 字号与描边字，回落后仍成立。
4. dev 条可能被误认为产品组件——文档与截图均标注"演示辅助"。
5. 刻度在 360 宽强制 compact 后变为 ×N 计数——记号让位于可读性，属设计内退化（双编码仍在）。
